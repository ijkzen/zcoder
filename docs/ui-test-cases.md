# UI 测试用例文档

> 版本：v1.1（评审完成 + 遗漏场景补充）
> 范围：zcode-remote Flutter 移动端全部用户可见交互。
> 编写方式：与项目所有者逐项评审确认；每条用例的「预期结果」以本文档为权威，代码行为与文档冲突时视为缺陷或需重新评审。
> 最后更新：2026-08-17
> 修订记录：v1.0 初版定稿（11 节 ~100 用例）；v1.1 遗漏排查补充 27 条（8 项边界决策 + 19 条推导用例），修订 TC-SES-017（创建后自动进入新会话）。

## 约定

- 每条用例格式：**前置条件**（用户处于何种情况）→ **操作** → **预期结果**。
- 用例 ID：`TC-<模块>-<序号>`，模块缩写：DEV=设备列表、SCAN=扫码、WS=项目列表、SES=会话列表、CONV=会话详情、REQ=审批/提问、MODEL=模型选择器、PROV=提供商管理、LOG=协议日志、GLOB=全局行为、MIX=组合操作。
- 边界情况以 ★ 标注；1xx 编号为评审确认的边界用例。

| TC-DEV-009 | 列表有设备 | 长按条目 → 输入合法新名 → 「保存」 | 列表显示新名称；杀进程重进后名称保持（已持久化） |

| TC-DEV-011 | 设备页 | AppBar 二级菜单 → 「模型提供商」/「协议日志」 | 分别 push 对应页面 |

### 1.2 边界用例（已评审确认）

| ID | 前置条件 | 操作 | 预期结果 |

| TC-DEV-105 ★ | 设备 A 已连接（活跃高亮） | 点击另一台设备 B | **断开 A 改连 B**：先断开与 A 的连接再连接 B；任意时刻单活动连接；B 成功后进入 B 的项目列表（与 TC-DEV-104 构成完整切换规则） |

| TC-WS-009 | 从会话列表返回项目页 | 观察列表 | 列表保持并随轮询刷新（运行中计数等状态最新） |

| TC-WS-011 | 项目列表（有内容或空状态） | 下拉刷新 | 重新发送 workspace-list-request；响应到达后列表/空状态更新（新增项目、运行中计数等） |

### 3.2 边界用例（已评审确认）

| ID | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|
| TC-WS-101 ★ | 项目含 N 个正在运行的会话 | 长按 → 删除确认框 | 确认框在会话总数（含已归档提示）基础上**额外明确警告「其中 N 个会话正在运行」**；确认后删除会中断这些会话 |
| TC-WS-102 ★ | 删除进行中（AbsorbPointer + 进度条） | 按系统返回键 | **返回被拦截**，停留在删除中状态直到出结果；不允许半路离开导致结果丢失 |

> **交叉说明（删除 vs 归档的不对称是刻意的）**：删除含运行中会话的项目是「警告后允许」（TC-WS-101），而归档单个运行中会话是「禁止」（TC-SES-101）。理由：删除是不可逆操作，用明确警告兜底；归档本身可逆、无确认门槛，若允许会把「仍在运行的任务」从视野中隐藏，用户容易误以为已停止，故直接禁止。
